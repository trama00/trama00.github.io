CUDA - GPU optimization

GPU matrix-vector multiplication at 30.7x over a naive CPU baseline.

A 16384 x 16384 matrix-vector product with a cubic term, optimized on a Tesla T4 with shared-memory reduction, vectorisation and loop unrolling. The remaining bottleneck is measured, not guessed.

Task

Compute sum_i( A[i][k] * b[k]^3 ) for a 16384 x 16384 unsigned char matrix (268 MB) against a 16384-element vector. The matrix does not fit in cache, so the problem is memory bound, not compute bound.

Results

  • Naive serial CPU — 966.72 ms
  • CUDA, two-kernel reduction — 31.52 ms
  • Speedup — 30.7x

Measured on an NVIDIA Tesla T4 (40 SMs, 320 GB/s peak memory bandwidth), with the result asserted against the CPU reference. The CPU baseline is a naive single-threaded loop, not BLAS, so the accurate claim is 30.7x over a naive serial implementation.

What made it fast

Thread-local accumulation so partial sums stay in registers; uchar4 vectorisation to quarter the number of load instructions; #pragma unroll 8 to reduce branches; a shared-memory binary-tree reduction so one value leaves each block; and a second reduction kernel that collapses the per-block partials without using atomics.

What is still wrong

The mapping is one thread per row, so consecutive threads read addresses 16 KB apart and every warp load is uncoalesced. Effective bandwidth measured 8.5 GB/s of a 320 GB/s peak, or 2.7%. The 30.7x is real but far from the hardware ceiling. The fixes are warp-per-row loads with a shuffle reduction, and precomputing b[k]^3 once instead of per element. Both are documented in the repository rather than implemented.
